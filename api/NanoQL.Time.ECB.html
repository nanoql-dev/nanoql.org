Remarks

The known dates are a value: Default holds QuantLib's, from January 2005 to December 2024, and AddDate(Date) and RemoveDate(Date) return a new value, so two calculations can use different sets and neither changes the other's. In QuantLib they are one static set that addDate and removeDate change for the whole process. Two values are equal when their known dates are.

QuantLib's functions whose date defaults to Date(), read as the global evaluation date, take the context after QuantLib's parameters without a default, and the date as a nullable after it: the context's evaluation date is read only when the date is null.

At the start of Date's range QuantLib steps one day before the month's first day, or before the date, and so throws on 1 January 1901 (ecb.hpp:42, :81-84; ecb.cpp:200): here a month's date is the first known date on or after its first day, and IsECBdate(Date) is membership in the known dates up to the last one, QuantLib's answers everywhere else; a documented divergence.

A method of this class is named Date, which hides the type inside it, so the class writes the type NanoQL.Time.Date.
