Remarks

A working type: mutable, owned by one computation and not thread-safe. Each draw changes it. A draw's sample holds the generator's own path, a view valid until the next draw, which overwrites it; a caller that keeps a path copies it. No draw allocates.

It copies the sequence generator it is given, so the caller's later draws from that generator change nothing in its paths, and Clone() copies it deeply. With the Brownian bridge, each sequence is first transformed into the variations of a bridge over the time grid.

The named shortcut classes derive from it; nanoql's own code uses the generic type. QuantLib takes any process and casts it to a 1-D one, failing later on a null; nanoql refuses a process that isn't 1-D when it is built.
