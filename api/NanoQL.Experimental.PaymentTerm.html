Remarks

Immutable. QuantLib's empty PaymentTerm() is a PaymentTerm? null. QuantLib keeps a process-wide registry keyed by name, so a second construction with a known name returns the first construction's event, offset and calendar whatever it was given (paymentterm.cpp:27-40). There is no registry here, so every term holds the data it is given, a documented divergence (Divergences/CommodityRegistryTests.cs).

Two terms are equal when their names are, compared ordinally, as QuantLib's operator== compares them (paymentterm.hpp:113-115); the hash is the name's.
