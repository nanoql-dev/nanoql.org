Remarks

Both stages run on the operator set once over the whole step, [t − dt, t], the interval QuantLib's other schemes set for their own steps: the sub-scheme steps without setting its operator's time. QuantLib's sub-step sets the operator over [t − α·dt, t] and its BDF2 stage solves with that operator, so with time-dependent coefficients QuantLib's scheme is first order or stalls; its own cases are all flat, where both stages' last bits move with the fix (Divergences/TrBdf2TimeDependentTests.cs). The boundary conditions keep QuantLib's times: the sub-step sets them to t − α·dt, and the stage to t − dt.

The fix holds over nanoql's seven one-step schemes, which can step on the set operator. A trapezoidal scheme of one's own steps as it always does, setting its operator over [t − α·dt, t], so the stage solves with that operator, as QuantLib's does.

A working type: Step(Span<double>, double) steps the caller's values in place through buffers the scheme holds, so a one-directional step allocates nothing after the first.
