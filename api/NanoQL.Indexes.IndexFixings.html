Remarks

Every change returns a new store, as .NET's immutable collections do. The writers take the index, whose name keys its history and whose IsValidFixingDate(Date) and AllowsNativeFixings QuantLib's checks read; an index reads its fixings through PastFixing(Date, EvaluationContext), HasHistoricalFixing(Date, EvaluationContext) and TimeSeries(EvaluationContext).

Names compare as QuantLib's do: ASCII letters upper-cased, every other character as it is, so "Euribor6M" and "EURIBOR6M" share a history. The first spelling stored is the one Histories() gives, in the order of that comparison.

Two stores are equal when they hold the same names, by that comparison, each with an equal history; which spelling was kept doesn't count. The hash combines one hash per history, each computed when its series was built.

Three divergences from QuantLib: a refused batch changes nothing, where QuantLib stores its valid fixings, and a null entry at the refused date, before it throws; reading never writes, where QuantLib's reads insert null entries and empty histories; and a fixing equal to QuantLib's null sentinel Null<Real>() (3.4028234663852886e38) is stored as a value, where QuantLib reads it as no fixing.

Remarks

The fixing is written on each date of the index's FixingDates(Date): the date alone, or for an inflation index every day of the date's inflation period, as QuantLib's InflationIndex::addFixing writes it. The dates are written together, through the same checks as AddFixings(FinancialIndex, IEnumerable<Date>, IEnumerable<double>, bool), all or nothing.

Exceptions

ArgumentException

A date isn't a valid fixing date, or a different fixing is stored on one and forceOverwrite is false.

NanoQLException

The index allows no native fixings.
