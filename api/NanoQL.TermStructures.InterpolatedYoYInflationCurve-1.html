Remarks

The first date is the base date and the first rate the base rate. The rates aren't year-on-year swap quotes. A rate is the interpolation's value at the start of the date's inflation period, extrapolated, with the seasonality's correction. The curve implements IInterpolatedCurve<TTraits, TInterpolator> over YoYInflationTraits, as the piecewise year-on-year curve does.

QuantLib's protected constructor without nodes, through which its piecewise curve derives, isn't ported: the piecewise curve implements the interface itself. An extension point, for its named class.

QuantLib reads the first date and the first rate before it checks how many there are, so with no date it throws std::out_of_range, and with no rate it reads past the end of the rates, which is undefined; here an empty list is refused first, with QuantLib's own "too few dates" or count mismatch: for no date the playbook's convention for such an exception, for no rate a documented divergence.

Exceptions

ArgumentNullException

dates, rates or dayCounter is null.

ArgumentException

There are fewer than two dates, a date is default(Date), the rates aren't one per date, a rate after the first isn't above -100%, the dates aren't sorted or two give the same time, or the interpolation refuses the points.

ArgumentOutOfRangeException

frequency isn't a member of its type.

NanoQLException

The seasonality is inconsistent with the curve.
