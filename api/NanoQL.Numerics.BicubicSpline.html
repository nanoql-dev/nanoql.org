Remarks

The matrix holds a row per y value and a column per x value: the value at (xi, yj) is zData[j, i]. Each row is a natural cubic spline in x (Spline, not monotonic, a second derivative of 0 at both ends), built with the interpolation; a value is the natural cubic spline in y through the rows' values at x, built at each call, each spline extrapolating outside its range. The x and y values must be sorted.

The five derivatives follow QuantLib's: DerivativeX(double, double) and SecondDerivativeX(double, double) differentiate the spline in x through the values at the x nodes, DerivativeY(double, double) and SecondDerivativeY(double, double) the spline in y of the value, and DerivativeXY(double, double) the spline in x of DerivativeY(double, double) at the nodes. As in QuantLib, they skip the range check Evaluate(double, double, bool) makes, and the spline they differentiate refuses a point outside its own range, whatever the extrapolation flag.

A matrix larger than the grid is read in its first rows and columns, as QuantLib reads it; a smaller one, which QuantLib reads past its end, is refused. It copies its inputs, as every Interpolation2D does, so a change of the caller's matrix is a new interpolation, where QuantLib's reads the matrix by reference until update().
