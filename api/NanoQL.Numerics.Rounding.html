Remarks

Immutable. QuantLib documents the precision's range as [0, 16] and doesn't check it, leaving other values undefined; nanoql refuses them when the rounding is built.

A rounding built with Rounding(), QuantLib's default construction, doesn't round and has no precision or rounding digit: Precision() and RoundingDigit() refuse it, where QuantLib reads two uninitialized members.

Parameters

The number of decimal places kept, in [0, 16].

type RoundingType

The rounding method.

digit int

The rounding digit: the first decimal place past the precision rounds up when it is at least this digit, for the methods that use it. It isn't checked, as in QuantLib: 0 always rounds up and 10 never does.
