Remarks

If no payment convention is given, the respective leg schedule's convention is used. The interest-rate indexes should be linked to valid forwarding curves, and, for swap indexes, discounting curves.

The constructors build the legs, as QuantLib's do: an Ibor leg with the index's default pricer, which reads the context's at-par switch, so they take the context; a CMS leg without a pricer, as QuantLib's, on which SetCouponPricer<T>(T, int, FloatingRateCouponPricer?) sets a CmsCouponPricer. A zero gearing becomes QuantLib's machine epsilon, so that the legs are built of floating coupons. The first leg is paid by a payer swap. An engine's results are a FloatFloatSwapResults, whose fair spreads FetchResults(InstrumentResults) derives from the legs' BPS when the engine gives none. QuantLib's setupArguments isn't ported: nanoql's engines read the legs.

Remarks

The fair spreads are the engine's when it gives them; otherwise each is derived from the NPV and its leg's BPS, and is null when that BPS is zero or unknown. The BPS route is exact for a leg with no cap or floor; DiscountingSwapEngine solves a capped or floored leg's fair spread instead.

Exceptions

ArgumentException

The results aren't a swap's, or a per-leg result has the wrong number of legs.
