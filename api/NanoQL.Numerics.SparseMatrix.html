Remarks

Reading an element returns zero where none is stored and stores nothing; writing one stores it, zero included, as uBLAS's element reference does. The storage is uBLAS's, which QuantLib's tests read: Index1Data holds each filled row's start in Index2Data (the stored elements' columns, sorted within a row) and ValueData, and Filled1 is one more than the last row written to.

As uBLAS's NDEBUG build, which QuantLib's builds use, indices aren't checked against the sizes, and the sum of matrices of different sizes has the smaller of each; an in-place sum refuses only a nonzero element outside the matrix: uBLAS writes a row outside past the matrix's row starts, and stores a column outside past its columns, which a product then reads past its vector.
