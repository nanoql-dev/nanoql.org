Remarks

The first date is the reference date, where the probability is 1. Past the last node the probability decays at the hazard rate there; the default density is minus the probability's derivative, and the hazard rate the base's. The curve implements IInterpolatedCurve<TTraits, TInterpolator> over SurvivalProbability, as the piecewise survival-probability curve does, so the ISDA engine's curve test accepts it as QuantLib's cast does.

QuantLib's protected constructors without nodes, through which its piecewise curve derives, aren't ported: the piecewise curve implements the interface itself. QuantLib reads the first date before it checks how many there are, so with no date it throws std::out_of_range; here an empty list is refused at that point with QuantLib's own "not enough input dates given", the playbook's convention for such an exception. An extension point, for its named class.

Exceptions

ArgumentNullException

dates, probabilities or dayCounter is null.

ArgumentException

There are fewer dates than the interpolator requires, a date is default(Date), the probabilities aren't one per date, the first isn't 1, one after it isn't positive or rises above the one before it, the dates aren't sorted or two give the same time, the interpolation refuses the points, or the jumps' dates don't match the jumps.
