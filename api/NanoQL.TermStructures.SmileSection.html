Remarks

An extension point, as in QuantLib: a section implements MinStrike(), MaxStrike(), AtmLevel() and VolatilityImpl(double), and may override the inspectors and the option prices, whose defaults price with Black's or Bachelier's formula on the section's variance.

Every section has a fixed reference date. QuantLib's floating section, built by date without a reference date, reads the evaluation date and re-reads it on each change; nanoql's concrete sections build it through a Create(…, EvaluationContext context) factory, which reads the date once (Create(Date, double, DayCounter, EvaluationContext, double?, VolatilityType, double)).

Remarks

QuantLib's default constructor leaves the exercise time, the volatility type and the shift uninitialized; here they are defined: an exercise time of 0, ShiftedLognormal and a shift of 0, with no exercise date, reference date or day counter.

Volatility(double, VolatilityType, double)

The volatility at a strike as a volatility of the given type and shift: the section's own where they are its own, otherwise the one implied by the section's out-of-the-money option price.

public double Volatility(double strike, VolatilityType type, double shift = 0)

Parameters

strike double

The strike.

type VolatilityType

The volatility type wanted.

shift double

The shift wanted, for a shifted lognormal volatility.

Returns

double

The volatility.

Remarks

As QuantLib's, it compares type with the type the section was built with, not with VolatilityType, which a subclass may override, and shift with Shift. A lognormal volatility is implied by Black's formula, or by Chambers' approximation where the solver fails.

Exceptions

NanoQLException

A conversion is needed and the section has no at-the-money level.
