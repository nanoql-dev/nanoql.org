Remarks

A calendar is immutable. AddHoliday(Date), RemoveHoliday(Date) and ResetAddedAndRemovedHolidays() return a modified copy and leave the receiver unchanged. In QuantLib the change applies process-wide, because every instance of a calendar shares one implementation.

Two calendars are equal when they are of the same type and have the same name and the same added and removed holidays, compared by content; the type keeps equality symmetric between a calendar and a subclass that compares more, such as JointCalendar. QuantLib's empty calendar, Calendar(), is null, and two empty calendars are equal: null equals null and no calendar.

A member that QuantLib lets take its empty calendar and uses unchecked takes null and behaves as QuantLib does: the empty calendar adjusts by Unadjusted and moves by weeks, months and years, and any other use throws NanoQLException, "no calendar implementation provided".

Remarks

The list stops at to, where QuantLib's loop steps one day past it (calendar.cpp:281) and so throws when to is MaxDate: a documented divergence.

Without weekends, it leaves out the days that are weekend days on their own date. QuantLib reads the weekend as IsWeekend(Weekday) answers it, today's, so for a market whose weekend changed on a date (the Tel Aviv stock exchange's in 2026, Tadawul's in 2013) its list holds every old-weekend day before the change: a documented divergence. Every other calendar's list is QuantLib's.
