Remarks

An extension point, as in QuantLib: the line searches derive from it (ArmijoLineSearch, GoldsteinLineSearch). A line search is a working type: Evaluate(ProblemState, ref EndCriteriaType, EndCriteria, double) changes it, and a search reads the state its previous call left (QuantLib's Armijo search reads the last gradient), so it isn't thread-safe.

A LineSearchBasedMethod holds one as a prototype and runs each minimization on a new one, NewSearch(), so the method stays immutable and a minimization's result doesn't depend on the minimizations before it, where QuantLib's method keeps one line search's state across them. The accessors return the search's own vectors, valid until it next changes.
