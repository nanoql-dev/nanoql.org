Builds a set of curves that form a dependency cycle, solving the bootstrapped ones together with one optimizer.

Remarks

The steps to set up the cycle's members:

  1. Create a MultiCurveMember for each member, with the member's reference date and day counter, to represent it: QuantLib's empty internal handle.
  2. Build the cycle's indexes and rate helpers on the members.
  3. Add each member with its curve's arguments: AddBootstrappedCurve<TTraits, TInterpolator>(MultiCurveMember, Date, IEnumerable<BootstrapHelper<YieldTermStructure>>, DayCounter, IEnumerable<double>?, IEnumerable<Date>?, TInterpolator, GlobalBootstrap) for a piecewise curve on a GlobalBootstrap, in either of the piecewise curve's forms, and AddNonBootstrappedCurve(MultiCurveMember, YieldTermStructure) for any other curve.
  4. Build(EvaluationContext): it builds the bootstrapped members, links each member once to its curve, bootstraps the bootstrapped curves jointly, every curve's data being set before any helper is priced, and returns the curves in the order they were added.

An immutable builder: each Add… returns a copy. The members are linked by Build(EvaluationContext), not by the Add… calls, since a curve is built in an evaluation context; a member already linked, or already added, is refused, so a second Build(EvaluationContext) of the same builder refuses. A non-bootstrapped curve reads the curves it references when it is queried, so it needs nothing from the joint bootstrap. QuantLib's checks that a curve is a multicurve bootstrap provider with a contributor have no counterpart: a bootstrapped member is built on GlobalBootstrap by Build(EvaluationContext) itself.
