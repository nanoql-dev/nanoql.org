Remarks

Every change returns a new registry, as .NET's immutable collections do. Default holds QuantLib's known rates, the euro's legacy currencies and the redenominated Turkish, Romanian and Peruvian currencies, which QuantLib's manager holds at start and after clear(). Add(ExchangeRate, Date?, Date?) puts a rate first among its pair's entries, so the latest added takes precedence where date ranges overlap; Lookup(Currency?, Currency?, EvaluationContext, Date?, ExchangeRateType) finds a direct, triangulated or chained rate in QuantLib's order.

QuantLib keys its rates by the pair's numeric codes, min × 1000 + max (exchangeratemanager.cpp:89-98), which loses every rate of a currency coded 1,000 or more (QuantLib's crypto currencies, 10000 to 10007, or any currency of one's own: a lookup from it throws, and no chain passes through it), and can't tell apart two currencies sharing a code (CNY and CNH, 156: a USD/CNH rate answers for USD/CNY). Here the key is the pair of currencies, ordered as QuantLib's key orders pairs, the codes and names breaking a tie; a chained lookup tests which pairs involve a currency and which currencies it has passed by the same identity, where QuantLib uses the numeric code (:95-98, :159, :170), and chains as QuantLib's chain does. So QuantLib's order and answers stand wherever the numeric codes are distinct and below 1,000 and the currencies' names distinct, BGL and BGN apart: three documented divergences (Divergences/ExchangeRateKeyTests.cs, Divergences/SharedNumericCodeTests.cs, Divergences/CurrencyNameAndCodeTests.cs).

Two registries are equal when they hold the same pairs, each with equal entries (rate, start and end dates) in the same order. The hash combines one hash per pair, computed when the registry is built.
