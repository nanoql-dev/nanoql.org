Remarks

QuantLib's parseFormatted, which runs Boost.Date_Time's format engine on a string, isn't ported: a date parsed by DateOnly.ParseExact converts to a Date.

QuantLib's parseISO checks the length and the dashes and reads each field with std::stoi, which stops at the first non-digit, so "2006-1a-15" parses as 15 January 2006 (dataparsers.cpp:106-114): here a field that isn't all digits is refused with QuantLib's "invalid format", a documented divergence.
