Remarks

QuantLib starts it from the trapezoid's estimate, as every policy (trapezoidintegral.hpp:58-82), which its refinement doesn't refine: the start's error then falls by a third per tripling, first order, so exp on [0, 1] at 1e-6 takes 531,442 evaluations where the midpoint start takes 2,187, and at 1e-10 it doesn't return. Here it starts from the one-interval midpoint estimate, (b − a)·f((a + b)/2), its own; a documented divergence.
