Remarks

An extension point. Every built structure has a fixed reference date: QuantLib's constructor that takes neither a reference date nor settlement days is the reference-date form, and the settlement-days form takes the reference date its concrete class's Create computed from the evaluation context.

BaseDate and Frequency aren't virtual, where QuantLib's are: the constructor's seasonality check reads them, and C# would run a derived override before the derived constructor. A derived curve passes its base date in; QuantLib's piecewise zero-inflation curve, whose base date is computed lazily, computes it at construction (the playbook's constructor-read row).

QuantLib's setSeasonality changes a built curve; here SetSeasonality<T>(T, Seasonality?, EvaluationContext) returns a copy of the receiver's type through WithSeasonality(Seasonality?, EvaluationContext), which a bootstrapped curve overrides to bootstrap its copy again.
