Remarks

Immutable, and an extension point: each of QuantLib's units derives from it (BarrelUnitOfMeasure, …), and a user may build one. QuantLib's empty UnitOfMeasure(), a placeholder whose members throw, is a UnitOfMeasure? null.

QuantLib's units are presets: each reads its data from Current when it is built (ResolveUnitOfMeasure(string, Func<UnitOfMeasureData>)), QuantLib's unless a provider configures them, its code QuantLib's always.

QuantLib keeps a process-wide registry keyed by name, so a second construction with a known name returns the first construction's data whatever it was given: UnitOfMeasure("Barrels", "B2", Mass) after ("Barrels", "BBL", Volume) has code BBL and type Volume (unitofmeasure.cpp:37-49). There is no registry here, so every unit holds the data it is given, a documented divergence (Divergences/CommodityRegistryTests.cs).

Two units are equal when their codes are, compared ordinally, whatever their other data, as QuantLib's operator== compares them (unitofmeasure.hpp:130-132); the hash is the code's. The equality is sealed, so every subclass compares the same way.

Every unit's rounding is QuantLib's default Rounding(), which leaves an amount as it is, where QuantLib's is Rounding(0), to the closest whole unit, which its public constructor can't change (unitofmeasure.hpp:82-86), so its automated conversions round a thousand-barrel quantity to thousands of barrels: 2 MB plus 1,500 BBL is 4 MB there, 3.5 MB here (Divergences/QuantityRoundingTests.cs).
