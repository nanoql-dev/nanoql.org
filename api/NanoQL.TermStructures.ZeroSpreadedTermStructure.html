Remarks

QuantLib's curve derives from RelativeDerivedYieldTermStructure<ZeroYieldStructure>, a class template over its own base, which C# can't express; it implements the template's members itself. Its reference date and day counter are the original's, read when it is built (a term structure has a fixed reference date), and so is its extrapolation flag; its calendar, settlement days and maximum date are the original's, read when they are asked for, and so are its zero rates. So it can be built on a MultiCurveMember before the cycle is built, whose reference date and day counter it reads then, as QuantLib builds it on an empty handle.

The spread is added in the given compounding and frequency: the original's zero rate at a time in them, plus the spread, converted to continuous compounding at that time. A spread or an original that changes is a new curve: QuantLib's curve follows its quote and its handle. A compounded rule with no frequency, the default frequency, builds and is refused at every query that reads a zero rate, as QuantLib's is.

QuantLib's constructor that takes a day counter, which it ignores, is deprecated and not ported.
