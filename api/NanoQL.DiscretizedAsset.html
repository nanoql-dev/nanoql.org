Remarks

A working type, as a random-number generator is: mutable, owned by one calculation and not thread-safe. An engine builds its assets inside its calculation, initializes them on a lattice, rolls them back and reads their value; no immutable object holds one.

Its values and buffers. Values is a view of the current step's values in the asset's own buffer, which the asset's code reads and writes as QuantLib's values_. The asset holds two buffers. A lattice reserves both at the widest step a rollback from the initial time passes through (ReserveCapacity(int)), then steps back into the spare one (StepValues(int)) and makes it the current one (CommitStep(int, double)), so a rollback allocates nothing, where QuantLib's allocates an array per step. A view is valid until the asset's next step or reset.

Adjustments. PreAdjustValues() and PostAdjustValues() run the protected PreAdjustValuesImpl() and PostAdjustValuesImpl() once per time: each remembers the last time it adjusted at, starting at QuantLib's QL_MAX_REAL, and, as QuantLib's, Initialize(Lattice, double) doesn't forget it, so an asset initialized again at its last adjustment time skips that adjustment.

An extension point, as in QuantLib: the discount bond, the option, the swap, the swaption and the callable bond derive from it, as later ports' cap, vanilla option, barrier and convertible assets will.
